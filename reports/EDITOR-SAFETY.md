# 연결 검사와 성능 회귀 방지

last_reviewed: 2026-10-08 · 범위: NNB 전략 에디터

에디터는 변경과 연결된 부분을 함께 검사하고, 알려진 충돌을 해결하기 전 **오프라인 시험본 생성**을 차단한다. 초안 저장은 허용한다. 검사를 통과해도 경기력이 유지됐다고 표시하지 않으며, 실전 승격이나 게임 실행 기능은 없다.

## 변경을 검토하는 단위

한 행동을 개선할 때 선행 건물·자원·증원·정찰·방어처럼 연결된 변경을 함께 검토한다. 서로 무관한 수정까지 묶어 성능 향상을 가정하지 않는다. 순정 기준본은 그대로 보존하고 변경 후보를 별도 폴더에서 비교한다.

| 바꾸는 부분 | 함께 확인할 부분 |
|---|---|
| 생산 순서·후속 운영 계열 | 선행 생산·전력·가스·보급, 순정의 후속 계열 전환 |
| 가스·일꾼·확장 기준 | 테크 자원, 중단 후 재개 범위, 생산과 확장 시점 |
| 공격 허용 | 첫 출발·증원·본진 방어, 러시 종료와 후속 테크 |
| 후퇴 기준 | 병력 손실, 적 정보, 공격·후퇴 반복 |
| 건물 간격 | 실제 건설 가능 위치·통로·전력 상실 |

## 구현된 차단과 경고

`tools/editor_safety.py`가 현재 프로필 전체를 검사한다. 브라우저가 검사 화면을 거치지 않아도 `editor_model.stage()`가 다시 검사한다.

- 새로 만들거나 수정한 빌드는 봇과 같은 BWAPILIB의 유닛·연구·업그레이드 자료로 확인한다. 누락된 선행 건물, 전력용 파일런, 가스 건물, 불가능한 연구 반복 횟수는 차단한다. 건설 시간·실제 가스 잔고를 시뮬레이션하지 않는다.
- 순정의 자동 파일런 보충이 가능한 보급 초과는 확정 실패로 단정하지 않고 타이밍 재검토로 표시한다. 가스 중단 이후 생산도 이미 모은 가스가 있을 수 있으므로 경기 확인 항목이다.
- 현재 시즌 맵에서 캐리어 후속 계열이 순정에 의해 드라군으로 바뀌는 선택은 차단한다. 질럿·드라군·드롭·다크 템플러 계열의 후속 순정 판단도 화면에 설명한다.
- 모순된 조건, 같은 범위에서 상반된 행동을 내는 규칙은 차단한다. 조건을 나누거나 **위쪽 규칙 우선**을 명시하면 후자는 경기 확인 항목으로 남는다. 순서를 바꾸거나 규칙을 지우면 무효가 된 우선 관계를 제거한다.
- 일시적인 적 정보에 `once`를 붙인 규칙, 겉으로 조건이 분리돼도 이전 발동이 유지될 수 있는 규칙은 해제·전환을 확인하도록 표시한다.
- 가스 일꾼 0명 설정 및 지속 가스 중단에는 재개 경로를 확인한다. 특정 맵만 포함하는 규칙을 모든 맵의 복구 경로로 인정하지 않는다. 범위와 조건이 형식상 유효해도 실제 도달 가능성과 발동 시간은 경기 검증 대상이다.
- 순정이 무시하는 `go ... then ...`, 수량과 숫자 인자가 함께 들어가 파싱되지 않는 명령, 비건물 위치 지정, 정수 오버플로를 차단한다.

순정 그대로인 22개 빌드를 이 검사로 새롭게 검증했다고 주장하지 않는다. 오류가 없다는 표시는 **지원하는 정적 검사에서 오류를 찾지 못했다**는 뜻이다. 경고 항목이 0개여도 실제 경기 검증은 필요하다.

## 연결된 선행 순서 수정

오류 옆 미리보기는 필요한 선행 항목을 재귀적으로 찾아, 뒤쪽의 단일 생산 항목을 앞으로 이동하거나 없다면 추가한다. `@ main` 같은 기존 위치 지정을 보존한다. 원본 초안은 그대로 두고 변경 목록·수정 전후 전체 순서를 보여 준다. 사용자가 **초안에 반영**을 누른 다음 저장해야 기록된다.

이 기능은 고수의 최적 빌드 자동 생성기가 아니다. 반복 생산이나 `then` 안에 있는 건물은 이동하지 못해 추가 건물이 생길 수 있다. 전후 건물 수와 자원 사용·타이밍을 함께 확인해야 한다. 수정 후 전체 검사를 다시 실행한다.

## 원인 확인 후 고친 설정 변환

- `ParseUtils::Get*ByRace`는 `self()->getRace()`를 읽는다. 에디터와 가스 검사도 내 종족인 Protoss 기준을 사용한다. 상대별 수치 변경은 종족전 조건 규칙으로 표현한다.
- 순정 `GetDoubleByRace`는 RapidJSON `IsDouble()`을 요구한다. 브라우저가 `2.0`을 `2`로 직렬화하면 값을 읽지 않고 0.0으로 돌아갈 수 있다. 내보낼 때 필드의 정수·실수 자료형을 복구하여 미네랄 포화 목표 등 수치가 무시되지 않게 했다. 수정한 빌드의 바깥 공백도 제거한다.

## 보존·복원·검증 근거

- 매 저장 전 버전은 `data/editor/history/<id>/<revision>.json`에 보존한다. 복원도 새 버전으로 저장하며 현재 상태를 보존한다. 오래된 창의 저장·복원은 거절한다.
- 각 시험본에 `profile.json`, `compatibility.json`을 넣는다. 보고서는 검사기 해시·프로필 지문·확인 항목을 담는다. manifest는 DLL·설정 해시와 `productionEligible:false`, `nativeGameTested:false`를 기록한다.
- 프로필을 끄면 편집 내용에 오류가 있어도 보존된 순정 DLL·설정으로 비교본을 만든다. 기존 게임과 설치 폴더에 복사하지 않는다.
- 이번 변경은 에디터·변환·검사 계층에 한정했다. 편집용 DLL과 보존된 순정 DLL의 기존 SHA256이 유지됐다.

회귀 검사 40개, x86 빌드·로드·팩터리 생성/파괴, UI 차단·수정 미리보기·초안 반영·명시적 우선 관계·저장본 왕복 복원·독립 시험본 생성이 통과했다. 실제 Remastered `onStart/onFrame`, 건설·생산·교전 성능은 아직 미검증이다.

성능 비교는 동일 맵·시작 위치·상대 조건에서 순정과 후보의 빌드 이행, 생산 정체, 정찰 생존, 방어 피해, 출발·합류·후퇴를 확인해야 한다. 사용자가 수집한 2500+ 리플레이의 같은 빌드·유사한 상황을 근거로 개선하고, 별도 평가 경기로 효과를 확인한다. 이 페이지의 통과 표시나 DLL 생성 성공을 승률·MMR 증거로 사용하지 않는다.
