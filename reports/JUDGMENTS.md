# 순정 판단 열람과 전략 추정 편집

검토: 2026-10-09 · 범위: NNB 전략 에디터 / Locutus 순정 기준

## 화면과 실행 연결

**조건과 판단**에는 세 탭이 있다.

- **순정 판단과 기본 기준**: 후퇴·확장·생산 정체·은폐/공중 대응의 기존 동작을 설명한다. 기존 18개 설정은 프로토스에게 적용되는 값과 순정 값을 함께 보여준다. 후퇴·확장 기준은 준비된 대응으로 복사해 수정할 수 있다.
- **정찰로 전략 추정**: `OpponentPlan.cpp`에서 실제 실행되는 여덟 판단의 조건, 검사 순서, 확정 여부와 후속 영향을 보여준다. 각 판단의 사용 여부·기준 수치·시간 범위가 `NNBPolicy.recognition`으로 내보내져 편집용 DLL에서 읽힌다.
- **내 추가 대응**: 빠른 러시·히드라 준비·본진 위협·후퇴·확장 예시에서 시작한다. 예시는 꺼진 상태이며 사용자가 켠 규칙만 실행된다. 추정 여부는 ‘해당함/해당하지 않음’, 공격 여부는 ‘공격 허용/방어 유지’로 선택할 수 있다. 미리보기는 상대 전략을 선택하면 실제 C++ 규칙 엔진에 해당 사실을 전달한다.

이 목록은 봇 전체 소스의 모든 판단을 편집 가능한 규칙으로 변환한 것이 아니다. 정찰 관측 수집, 벽을 찾는 지형 계산, 분기 순서와 논리 연산, 탐지 유닛·캐논 생산 전체 알고리즘은 그대로 남아 있다. 정찰 추정 화면은 저장된 기준을 보여주며 실시간 경기 대시보드가 아니다. 과거 상대 기록을 통한 예상 전략과 현재 경기의 정찰 추정도 구분한다.

## 원래 동작과 정보의 뜻

| 순서 | 실제 추정 | 조건의 핵심 | 확정 |
|---|---|---|---|
| 1 | 본진 안 전진 건물 | 정보 관리자가 본진 안 전진 건물을 확인 | 예 |
| 2 | 일꾼 러시 | 초반 제한 시간, 본진 중심 거리, 현재 보이는 적 일꾼 수 | 아니오 |
| 3 | 아주 빠른 러시 | 풀·게이트·배럭 또는 저글링·질럿·마린의 추정 시각 | 예 |
| 4 | 초고속 러시 아님 | 미확정 상태의 일꾼 수 또는 안전장치 시간 | 아니오 |
| 5 | 초반 병력 집중 | 많은 저글링, 적은 드론의 1해처리, 가스 미확인의 다수 생산 건물 등 5개 경로 | 예 |
| 6 | 히드라 공격 준비 | 해처리·히드라 덴 확인, 저글링 수와 시간 | 예 |
| 7 | 테란 입구 막기 | 테란 상대, 벽 확인, 시간 | 예 |
| 8 | 다크 템플러 | 다크 템플러 확인 수와 시간 | 예 |

순정은 100프레임 이후 10,000프레임 이전에 `frame % 12 == 7`일 때 검사한다. 이미 확정된 판단은 갱신하지 않으며 빠른 위협을 느린 판단으로 덮어쓰지 않는 기존 가드를 유지했다. 모든 기본값과 비교 연산은 고정 upstream `4e96da0b7e31831ee97aaef153b2bef977a235e1`에서 가져왔다. 설정 스키마는 `tools/judgment_catalog.py`, 생성된 실행 헤더는 `NNBPlanSettings.h`이다.

관측 수치는 `PlayerSnapshot::takeEnemy()`의 기억된 적 정보다. 미완성 건물은 포함하고 미완성 병력은 제외한다. 건물의 시각은 건설 시작 추정, 초반 병력은 이동 거리를 역산한 생산 완료 추정이다. 최초 발견 시각과 같지 않다. 가스 건물 0은 실제로 없다는 확증이 아닐 수 있다. 일꾼 러시 센서는 현재 보이는 일꾼만 센다. 숨겨진 상대 정보를 새로 읽는 경로는 추가하지 않았다.

팩토리 테크·방어 확장·무방비 확장·수비 집중 분기는 순정의 조기 `return` 뒤에 있어 실행되지 않는다. 화면에서도 비활성 설명으로 남기고 임의로 활성화하지 않았다.

추정을 바꾸면 순정의 정찰 지속, 가스 견제, 방어 병력·캐논, 테크 전환에도 영향을 줄 수 있다. 연결 영향 검사에 이를 표시하고, 전체 또는 개별 추정을 꺼 놓은 채 그 추정이 참이어야 하는 활성 대응은 시험본 생성을 차단한다. 일꾼 러시·초고속 러시 아님처럼 바뀔 수 있는 추정에 영구 유지 대응을 붙이면 복귀 경로를 검토하도록 표시한다.

## 오프닝을 읽고 수정하는 방식

원래 프로토스 빌드 22개에 한국어 이름과 설명을 붙였다. `DTDrop`은 ‘앞마당 후 다크 템플러 드롭’, `Singularity Charge`는 ‘드라군 사거리 업그레이드’다. 표시 이름은 게임이 읽는 빌드 키를 바꾸지 않는다.

번호는 인구수가 아닌 실행 단계다. `pylon then go scout while safe`는 **파일런 건설 시작 → 안전한 동안 일꾼 정찰**로 표시한다. Protoss 건물의 연결 행동은 착공 시점, 연구·업그레이드 연결 행동은 완료 시점이다. 단순 유닛 생산 뒤의 연결 명령은 실제 지원되지 않으므로 쉬운 폼에서는 만들 수 없다. 가스 목표는 소비한 가스를 계속 채우는 잔고 목표가 아니고, 공격 시각은 병력 수가 아닌 게임 시간이다.

각 단계의 수정 버튼에서 행동·반복 수·건설 위치·시간·연결 행동을 고른다. 읽거나 번역하는 것만으로 명령 문자열을 다시 저장하지 않으며 명시적인 반영 때만 직렬화한다. 원문은 접힌 고급 편집에 남긴다. 해석하지 못하는 항목은 임의로 바꾸지 않고 원문 확인을 안내한다.

## 검증과 한계

- `scripts/build-editor.ps1`: x86 DLL 빌드·로드·생성·파괴 및 49개 회귀 검사 통과.
- `nnb-plan-regression`: 고정 upstream과 수정 소스에서 `recognize/update/fastPlan` 실제 함수 본문을 추출하여 같은 합성 입력으로 156,000번 비교했다. 기본 설정의 추정 결과·확정 상태가 같았으며, 기준 변경·추정 끄기·잘못된 시간 범위 거절도 확인했다. 관측 센서·거리 계산·실제 게임을 실행한 검사는 아니다.
- 원본 프로토스 오프닝 전 항목의 한국어 해석과 명령 왕복 보존 확인. 건설 시작/업그레이드 완료 구분, 시간 단위와 지원하지 않는 연결도 검사했다.
- 브라우저에서 빌드 표시 이름·파일런 위치·연결 정찰의 편집/저장, 기존 후퇴 설정 저장, 히드라 기준 2→3의 실제 내보내기, 순정 기준 복원을 확인했다. 추정 전략을 히드라/빠른 러시로 바꾸었을 때 방어 규칙의 충족/미충족도 실제 엔진으로 확인했다.
- 데스크톱과 500px 폭 화면에서 오프닝 폼·추정 기준·대응 편집을 확인했고 콘솔 오류가 없었다. 검사용 프로필은 꺼 두었다. 기존 사용자 프로필과 순정 DLL 해시는 변하지 않았다.

Remastered `onStart/onFrame`, 실제 정찰 정확도·생산·교전·승률은 아직 검증하지 않았다. 이 작업은 게임을 실행하거나 종료하지 않았다. 설정 편집과 기본값 비교 통과를 경기 성능 보장으로 해석하지 않는다.
