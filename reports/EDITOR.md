# NNB 전략 에디터

검토: 2026-10-08 · 범위: NNB / Locutus 후속 개발

로컬 주소: <http://127.0.0.1:8830/>. 시작 명령은 `scripts/start-editor.ps1`, 편집용 DLL과 검사기 빌드는 `scripts/build-editor.ps1`이다. 스타크래프트와 래더 실행은 하지 않는다.

## 사용하는 순서

1. **순정 Locutus**를 선택해 기준을 확인하고 **복사본 만들기**를 누른다.
2. **오프닝 빌드**에서 PvP/PvT/PvZ별 사용할 빌드를 고른다. 고정 체크를 켠 종족전에만 해당 선택이 우선한다. 나머지 종족전의 순정 학습과 맵 선택은 유지한다.
3. 빌드를 복사하고 한국어 선택기로 생산물·수량·건물 위치를 추가한다. 위아래 버튼으로 순서를 바꾼다. 원문 입력은 Locutus의 기존 명령 문법이다. 선행 순서·가스 건물은 연결 검사에서 확인하며, 완공 시간·자원 잔고·실제 건설 가능 여부는 경기 검증이 필요하다.
4. **운영과 컨트롤**에서 경제·정찰·생존 기준을 조정한다. 여기의 종족별 값은 상대가 아닌 **내 종족**이다. NNB 프로토스는 Protoss 값을 읽는다. **조건과 판단**에서 ‘언제, 어느 맵·종족전·빌드에서, 어떻게 판단할지’를 선택하고 참고 리플레이와 고려 사항을 기록한다.
5. **맵 지형**에서 기지·길목·지상 거리를 확인하고, **고수 리플레이**에서 같은 맵 해시·빌드·시간과 유사한 일꾼/기지 상황을 검색한다. 다른 맵을 자동 대체하지 않는다.
6. **연결 영향 검사**에서 생산·자원·정찰·교전·배치 영향을 확인한다. 누락된 선행 항목은 이동·추가할 내용과 전체 전후 순서를 보고 초안에 반영한다. 충돌 규칙은 조건을 나누거나 의도한 우선 관계를 명시한다.
7. 저장, 연결 검사, 상황별 판단 확인 후 **오프라인 시험본 만들기**를 누른다. 알려진 오류는 서버에서도 생성을 차단한다. 새 `artifacts/editor-*` 폴더에 DLL·설정·9맵 캐시·원본 프로필·연결 검사 보고서·manifest가 생긴다. 이미 실행 중인 게임은 바뀌지 않는다.
8. **검사와 반영 → 이전 저장본으로 되돌리기**에서 저장 번호를 선택한다. 복원 전 상태도 보존하고 새 저장 번호로 복원한다.

검사 계약과 실제 코드 근거는 [연결 검사와 성능 회귀 방지](EDITOR-SAFETY.md)에 둔다. 여러 부분을 함께 고치는 것만으로 성능이 보장되지는 않는다.

## 실제로 편집되는 범위

| 영역 | 편집 내용 | 실행 연결 |
|---|---|---|
| 오프닝 | 순정 22개 프로토스 전략의 복사·순서·횟수·위치·정찰/공격 명령, 종족전별 고정, 후속 운영 계열 | 기존 ParseUtils / MacroAct / StrategyManager |
| 경제·생산 | 가스 일꾼, 미네랄 포화 목표, 전체 일꾼 상한, 생산 정체 대기, 건물·파일런 간격 | 원래 설정 파서 및 Worker/Production/Building 판단 |
| 정찰·마이크로 | 원거리 치고 빠지기, 일꾼 방어, 근접 체력·보호막 후퇴 기준, 판단 거리, 정찰 견제·가스 러시·전략 인식·순정 기권 | 원래 설정과 해당 관리자 |
| 조건 정보 | 게임 시간·자원·인구·완성 일꾼/기지/유닛 수, 병력 자원 가치, 현재 보이는 적 유닛/병력, 기지 근처 적, 적 본진·은폐 기술 확인 | NNBPolicy가 관측값으로 생성; 숨겨진 적 상태 미사용 |
| 조건 행동 9종 | 공격 허용, 전투 점수 후퇴 기준, 재공격 대기, 확장 일꾼/쉬는 일꾼 기준, 일꾼 상한·가스 일꾼·근접 체력/보호막 | CombatCommander, Squad, StrategyManager, Config 조정 |

모든 조건은 AND로 결합한다. 여러 규칙으로 대안을 표현할 수 있으며 같은 행동이 충돌하면 위쪽 규칙이 우선한다. `while`은 조건이 풀리면 원래 값으로 돌아간다. `once`는 한 번 만족한 규칙을 그 경기 동안 유지한다. 평가는 8프레임 간격이다. 근접 교전·긴급 방어·생산의 다른 순정 판단은 함께 작동한다.

3질럿 예시는 꺼진 상태로 추가된다. 선택한 PvP 빌드에서 첫 3기가 완성되면 공격 허용을 유지하며, 병력을 잃어도 5·7기를 다시 기다리는 조건을 만들지 않는다. 이는 **3기 동시 출발 위치·후속 유닛의 정확한 이동 경로까지 검증된 구현**이라는 뜻이 아니다. 참고용 규칙이며 실제 10/12 생산 순서나 고수 플레이를 자동 설치하지 않는다.

`NNB-decisions.jsonl`에는 충족 규칙 목록이 바뀔 때 게임 프레임, 사용 조건의 관측값과 최종 행동 값이 남는다. 기권 휴리스틱 및 전투 계산 점수는 보정된 승률이 아니다.

## 순정 보존과 반영 경계

- 기준 설정은 고정 upstream 커밋에서 읽는다. 기준 프로필에 대한 저장은 거절한다. 원래 `Locutus.json`은 변경하지 않았다.
- `build-baseline.ps1`은 upstream 아카이브를 새 폴더에 풀어 빌드한다. 현재 편집 소스를 순정으로 재빌드하지 않는다. 이미 보존한 `artifacts/upstream/NNB.dll`은 덮어쓰지 않는다.
- 프로필을 끄면 **순정 DLL과 설정**으로 실행본을 생성한다. 편집용 실행본에는 빌드 소스와 DLL 해시가 일치해야 한다. 소스만 고친 뒤 오래된 DLL을 배포하려 하면 거절한다.
- 각 실행본은 독립 폴더다. 검증 캐시가 하나라도 없거나 해시가 다르면 생성을 멈춘다. 기존 경기 기록·프로필·게임 설치 폴더를 덮어쓰지 않는다.
- 공개 저장소에 맵 파일·리플레이·기기 경로·DLL을 올리지 않는다. 로컬 `data/`, `build/`, `artifacts/`에 남긴다.

## 확인한 결과와 남은 범위

통과: 편집용 x86 DLL 빌드 및 로드/생성/파괴, 원본 분리 빌드 및 같은 스모크 검사, Python/실제 C++ 엔진 회귀 검사 40개, 9맵 원본 캐시 로더 검사. 브라우저에서 기존 편집·지도·리플레이 조회 외에 선행 누락 차단 → 이동 미리보기 → 초안 반영 → 시험본 생성, 규칙 충돌 → 우선 관계 명시, 이전 저장본 복원 → 재복원을 확인했다. 새 연결 검사도 데스크톱과 좁은 화면에서 확인했다.

아직 검증하지 않은 것: Remastered 연결기의 NNB `onStart/onFrame`, 실제 게임에서의 건설·길찾기·생산·전투, 승률/MMR. 현재 켜진 스타크래프트 리플레이와 종료된 래더 실험은 유지했다.

이 에디터는 노출된 실행 기준을 수정한다. 미네랄 사이로 숨기기, 지정 해처리 타격, 개별 유닛 좌표 이동처럼 새로운 행동 알고리즘을 임의의 문장만으로 생성하지 않는다. 해당 행동은 별도 C++ 구현·관측 조건·같은 맵/빌드/상황의 리플레이 근거·오프라인 검증을 추가해야 편집 가능 항목으로 승격한다. 지형 거리·길목 폭은 현재 지도 열람 정보이며 규칙 조건에 자동으로 주입하지 않는다.
